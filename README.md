# 图片入戏：剧情聊天里的图片玩法 Demo

在 AI 角色的剧情聊天里，用户发来的照片不只是聊天内容，而是**剧情里的一个动作**。这个 demo 用真实照片和多模态模型，演示两种玩法。

## 玩法

**现实道具召唤**
角色在剧情节点开口要一件东西，用户拍下身边的真实物品。模型先客观识别物品，再按当前剧本的世界观把它转译成道具（名字、稀有度、属性、用途），并让剧情往前走一步。同一张照片在奇幻、恋爱、悬疑等不同剧本里会得到完全不同的结果。

发图后有旁白推进剧情，可以继续打字聊天。角色只在剧情需要时再要下一件东西，请求出现时只能发照片。

**视觉解谜**
密室潜入。每道锁有一条明确的通关条件（蓝色、圆形、数字），用户拍一张符合条件的照片，模型给出通过与否、依据和把握程度。过锁后可以聊天，聊几轮再触发下一道锁。

## 设计要点

- **感知和表达分层**：模型先输出客观识别结果，再按剧本转译。右侧面板展示每次调用的识别、转译、结果和原始 JSON。
- **台词不是看图说话**：物品细节最多提一处，重点是角色的态度和行动。
- **图片请求有节奏**：两次请求之间至少隔几轮对话，避免每句话都在要图。
- **不符合预期的输入由角色接戏**：照片看不清或条件不满足时，角色在戏里请用户再来一次，不弹系统报错。
- **剧场规则是硬约束**：例如观光向剧本禁止出现危险和紧急事件，写在提示词里强制执行。

## 目录

```
public/index.html   前端页面（单文件，无构建步骤）
api/ask.js          后端接口：可选口令、限流、转发给模型接口
vercel.json         接口超时设置
.env.example        环境变量示例
```

## 部署到 Vercel

1. 把本仓库导入 Vercel（Add New → Project），Framework 选 Other。
2. 添加环境变量：

   | 变量 | 必填 | 说明 |
   |---|---|---|
   | `GATEWAY_KEY` | 是 | 模型接口的 Key |
   | `GATEWAY_BASE_URL` | 是 | OpenAI 兼容接口地址，以 `/v1` 结尾 |
   | `GATEWAY_MODEL` | 是 | 支持图片输入的模型名 |
   | `ACCESS_CODE` | 否 | 访问口令。设置后打开页面要先输入口令 |
   | `REASONING_EFFORT` | 否 | 固定推理档位：`low` / `medium` / `high`，填 `none` 则不传该参数 |
   | `PER_IP_LIMIT` | 否 | 每个 IP 每 10 分钟的调用上限，默认 40 |

3. 点 Deploy。

本地调试：`npm i -g vercel`，复制 `.env.example` 为 `.env` 并填写，然后 `vercel dev`。

## 安全注意

- Key 只放在托管平台的环境变量里，不要写进代码或提交到 Git。`.gitignore` 已忽略 `.env`。
- 不设 `ACCESS_CODE` 时，任何拿到网址的人都能消耗你的额度。
- 接口自带的按 IP 限流是进程内计数，只能粗略防刷。
- 照片只在请求时转发给模型接口，服务端不保存。聊天记录只在浏览器内存里，刷新即清空。

## 说明

- 后端按 `/chat/completions` 格式调用，图片以 base64 data URL 传入。
- 「Neon Void strain」剧本改编自同名用户创作剧场，世界观与角色设定归原作者所有；其余剧本为本项目原创。
